# TASK-002: Окно настроек (виджеты, порядок, автозапуск, экран, общие параметры)

## Бизнес-цель
Пользователь сам собирает свою чёлку: включает нужные виджеты, задаёт порядок и общие параметры. Это центральная идея продукта («пихнем всё, но настраиваем»).

## Зависимости
TASK-001 (WidgetRegistry, config.json, протокол NotchWidget, меню-бар). Настройки отдельных виджетов подключаются из TASK-003..008 через точку расширения.

## Описание
Окно настроек (SwiftUI `Window`/`Settings` scene; приложение — агент `LSUIElement`, поэтому при открытии окна временно переключаем activation policy на `.regular`, чтобы окно получало фокус, и возвращаем `.accessory` при закрытии — неочевидный момент macOS).
Открывается из меню-бара «Настройки…» (⌘,). Одно окно: повторное открытие поднимает существующее.

Разделы (sidebar):
1. **Общие**: запуск при входе в систему (`SMAppService.mainApp`), выбор экрана (Авто / Основной / С чёлкой / конкретный из списка; соответствует `general.displayMode` из TASK-001). Язык интерфейса не настраивается (следует системному). Скрытие иконки меню-бара — вне scope.
2. **Виджеты**: список всех зарегистрированных виджетов с переключателем «включён» и перетаскиванием для изменения порядка. Порядок = порядок вкладок в expanded и тайбрейк в peek.
3. **Страница каждого виджета** (подпункт под «Виджеты» или раскрытие строки): настройки, предоставляемые самим виджетом через `makeSettingsView()`. Если у виджета нет настроек — страницы нет.
4. **О приложении**: версия, ссылка на папку с конфигом («Показать в Finder»), кнопка «Сбросить настройки», примечания по приватности (в т.ч. что виджет «Погода» отправляет координаты выбранного города в Open-Meteo, и атрибуция).

Расширяемость: виджет публикует свои настройки как Codable-структуру, хранящуюся в `widgets[i].settings` config.json; окно настроек не знает деталей виджетов. Добавление нового виджета не требует правок окна настроек, кроме регистрации в registry.

## Критерии приёмки (Acceptance Criteria)
- [ ] AC-1: Дано меню-бар, когда пользователь выбирает «Настройки…» или нажимает ⌘, при открытом меню, тогда открывается окно настроек и получает фокус.
- [ ] AC-2: Дано окно уже открыто, когда снова выбрано «Настройки…», тогда существующее окно выходит на передний план, второе не создаётся.
- [ ] AC-3: Дано окно настроек закрыто, тогда приложение возвращается в режим без иконки в Dock.
- [ ] AC-4: Дано раздел «Виджеты», тогда перечислены все зарегистрированные виджеты (включая выключенные) с названием, иконкой и переключателем.
- [ ] AC-5: Дано виджет включён, когда пользователь его выключает, тогда он исчезает из expanded/peek немедленно (≤ 300 мс, без перезапуска), вызывается `deactivate()`, config.json обновлён.
- [ ] AC-6: Дано виджет выключен, когда его включают, тогда он появляется в expanded на своей позиции и (если активен) участвует в peek; запрос системных разрешений — только в этот момент либо при первом обращении к данным (лениво), не при старте приложения.
- [ ] AC-7: Дано список виджетов, когда пользователь перетаскивает строку на новое место, тогда порядок вкладок в expanded меняется без перезапуска и сохраняется в config.json.
- [ ] AC-8: Дано выключены все виджеты, тогда чёлка остаётся (collapsed), expanded показывает пустое состояние «Нет включённых виджетов» со ссылкой «Открыть настройки».
- [ ] AC-9: Дано переключатель «Запускать при входе», когда пользователь включает, тогда регистрируется `SMAppService.mainApp`; состояние переключателя всегда читается из `SMAppService.status`, а не из config.
- [ ] AC-10: Дано регистрация автозапуска завершилась ошибкой или статус `requiresApproval`, тогда переключатель возвращается в фактическое состояние, показывается понятное сообщение и кнопка «Открыть Системные настройки → Объекты входа».
- [ ] AC-11: Дано выбор экрана, тогда список содержит «Авто (экран с чёлкой, иначе основной)» — по умолчанию, «Основной», «С чёлкой (если есть)» и подключённые экраны по имени; смена применяется к NotchWindow немедленно и пишется в `general.displayMode`/`displayId`.
- [ ] AC-12: Дано выбранный конкретный экран отключён, тогда чёлка переезжает на основной, а выбор в настройках сохраняется (и применится при возвращении экрана); в UI отображается «(не подключён)».
- [ ] AC-13: Дано у виджета есть настройки, тогда они доступны в настройках, изменения применяются на лету (без кнопки «Сохранить») и сохраняются в `widgets[i].settings`.
- [ ] AC-14: Дано виджет без настроек, тогда в окне настроек для него нет пустой страницы.
- [ ] AC-15: Дано «Сбросить настройки», тогда показывается подтверждение; после подтверждения config сбрасывается к дефолтам, данные пользователя виджетов (заметки, состояние таймера, кеш погоды в `data/`) НЕ удаляются.
- [ ] AC-16: Дано изменение любой настройки и немедленный выход из приложения, тогда изменение не потеряно (flush при завершении).
- [ ] AC-17: Дано регистрация нового виджета в коде, тогда он появляется в списке настроек без изменения кода окна настроек.

## Нефункциональные требования
- Окно открывается ≤ 300 мс; в закрытом состоянии окно/его view-модель не держат подписок и таймеров (0% CPU).
- Все изменения идут через единый `WidgetRegistry`/`ConfigStore`; окно настроек — только представление, прямых записей в файл нет.
- Доступность: полная навигация с клавиатуры, VoiceOver-метки у переключателей и drag-handle; для порядка есть альтернатива перетаскиванию (кнопки «Выше/Ниже» или контекстное меню).
- Окно изменяемого размера с минимальным размером, тёмная/светлая темы.
- `general` в config.json: `launchAtLogin` — только справочное поле (источник истины — SMAppService).

## Граничные случаи
- Запуск приложения не из /Applications (Debug-сборка, из DerivedData): `SMAppService` может вернуть ошибку/неожиданный статус — показываем сообщение, не падаем.
- Пользователь убрал приложение из Объектов входа в Системных настройках вручную — при следующем открытии настроек переключатель отражает реальный статус.
- Быстрое многократное переключение виджета — состояние консистентно, без гонок `activate/deactivate`.
- Перетаскивание на то же место / за пределы списка — порядок не меняется.
- Виджет с неизвестным id в config (из будущей версии) — в списке не показывается, в файле сохраняется.
- Config повреждён при открытии — см. TASK-001 AC-14.

## Не входит в задачу (Out of scope)
- Настройки внешнего вида (темы, размеры, цвета чёлки), горячие клавиши, режим «только клик».
- Переключатель языка интерфейса, режим «на всех экранах».
- Скрытие иконки меню-бара.
- Импорт/экспорт настроек, синхронизация через iCloud.
- Сами настройки конкретных виджетов (реализуются в TASK-003..008 через точку расширения).
- Автообновления (Sparkle).

## Принятые решения
- Q1: Нужен ли переключатель языка? → Нет, следуем системному языку (согласовано с TASK-001 Q6).
- Q2: Выключение виджета удаляет его данные? → Нет, данные сохраняются; удаление — отдельным действием в настройках виджета (где применимо, например «Очистить заметки»).
- Q3: Можно ли отключить все виджеты? → Да, пустое состояние (AC-8).
- Q4: Окно настроек отдельным окном или вкладкой в expanded? → Отдельное стандартное окно (фокус и ввод работают штатно).
- Q5: Нужна ли кнопка «Сбросить настройки»? → Да, без удаления данных виджетов (AC-15).

Открытых вопросов нет.
