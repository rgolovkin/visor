# TASK-006: Виджет «Быстрые заметки»

## Бизнес-цель
Мгновенно записать мысль, не открывая отдельное приложение, и найти её позже. Заметки — самые ценные пользовательские данные в проекте: потеря недопустима.

## Зависимости
TASK-001, TASK-002. `id: notes`. Особенность окна: NotchWindow по умолчанию не key-окно (TASK-001), поэтому для ввода текста используется механизм из TASK-001 (Q9, AC-22): окно становится key только при клике в поле ввода, автосворачивание отключено на время ввода (Q1).

## Описание
**Compact (peek)**: не участвует (`isActive = false` всегда, приоритет 0).

**Expanded**: слева список заметок (первая строка как заголовок + превью + время изменения), справа/вместо — редактор простого текста. Кнопки: «Новая», «Удалить», поиск по тексту. Последняя открытая заметка запоминается. Заметка создаётся пустой и автоматически удаляется, если осталась пустой при уходе.

**Редактор**: простой текст (plain text), моноширинный/системный шрифт, автосохранение. Без форматирования и Markdown-рендера (Q2).

**Хранение**: файл `~/Library/Application Support/NotchApp/data/notes.json` (платформонезависимо):
```json
{ "schemaVersion": 1,
  "notes": [ { "id": "uuid", "text": "...", "createdAt": "2026-10-12T10:00:00Z", "updatedAt": "2026-10-12T10:05:00Z", "pinned": false } ] }
```
Запись атомарная (temp + rename), debounce ≈ 500 мс после последнего ввода и принудительно при закрытии панели/выходе/потере фокуса.

**Настройки** (`widgets[].settings`): `sortBy` (updated/created, по умолчанию updated), `fontSize` (12–18, по умолчанию 13), `deleteConfirmation` (true), `pinnedFirst` (true).

## Критерии приёмки (Acceptance Criteria)
- [ ] AC-1: Дано вкладка «Заметки», когда нажимается «Новая», тогда создаётся пустая заметка и курсор стоит в редакторе.
- [ ] AC-2: Дано expanded открыт по hover, когда пользователь кликает в редактор, тогда окно становится key (только по клику в поле) и текст вводится, включая русскую/английскую раскладку, ⌘V, ⌘Z, выделение; после ухода курсора панель не закрывается, пока поле в фокусе (в т.ч. при IME-композиции); после потери фокуса полем или клика вне панели — сворачивается по обычным правилам (TASK-001 AC-22).
- [ ] AC-3: Дано введён текст, когда прошло 500 мс без ввода, тогда заметка записана в notes.json; при аварийном завершении (kill -9) через 1 с после ввода потеряно не более последних 500 мс.
- [ ] AC-4: Дано панель закрывается (hover ушёл/Quit) с несохранёнными изменениями, тогда изменения сохраняются синхронно до закрытия.
- [ ] AC-5: Дано список заметок, тогда они отсортированы по настройке, закреплённые — сверху; в строке — заголовок (первая непустая строка, усечена) и время.
- [ ] AC-6: Дано поиск по подстроке (регистронезависимо, кириллица работает), тогда список фильтруется на лету ≤ 100 мс на 1000 заметок.
- [ ] AC-7: Дано «Удалить», тогда запрашивается подтверждение (если включено), заметка исчезает; отмена удаления (⌘Z) вне scope, поэтому подтверждение по умолчанию включено.
- [ ] AC-8: Дано пустая заметка при уходе с неё, тогда она автоматически удаляется без подтверждения.
- [ ] AC-9: Дано виджет выключен в настройках, тогда заметки не удаляются и появляются при повторном включении.
- [ ] AC-10: Дано notes.json повреждён/нечитаем, тогда файл переименовывается в `notes.json.broken-<timestamp>`, создаётся пустое хранилище, пользователю показывается сообщение с путём к бэкапу; данные не теряются молча.
- [ ] AC-11: Дано notes.json с `schemaVersion` новее известной, тогда файл не перезаписывается (read-only режим с предупреждением) — защита от потери данных при даунгрейде.
- [ ] AC-12: Дано заметка длиной 1 МБ текста, тогда UI остаётся отзывчивым; лимит на заметку 1 МБ с понятным сообщением при превышении.
- [ ] AC-13: Дано файл заметок изменён вручную/другим процессом во время работы, тогда приложение не затирает чужие изменения молча: перед записью сверка mtime; при конфликте текущая версия сохраняется рядом как `notes.conflict-<timestamp>.json` (Q3).
- [ ] AC-14: Дано `sortBy`/`fontSize` изменены в настройках, тогда применяются немедленно и сохраняются в `widgets[i].settings` config.json.

## Нефункциональные требования
- 0% CPU в простое; нет таймеров, кроме одноразового debounce записи.
- Данные только локально, без сети; не логируются (содержимое заметок не попадает в логи).
- Загрузка 1000 заметок при открытии вкладки ≤ 200 мс (ленивая загрузка при первом показе, а не при старте приложения).
- Формат файла стабилен и документирован, чтобы Windows-клиент мог читать тот же файл.

## Граничные случаи
- Нет места на диске / нет прав записи — ошибка видна пользователю, текст остаётся в памяти, повторная попытка при следующем изменении.
- Эмодзи, RTL, очень длинные строки без переносов.
- Вставка большого текста; вставка форматированного (приводится к plain).
- Одновременное изменение времени и сортировка при редактировании: активная заметка не «прыгает» из-под курсора во время ввода (пересортировка при потере фокуса).
- Дубликаты id при ручном редактировании — вторая запись получает новый id.
- Hover уходит во время IME-композиции (ввод на китайском/японском) — панель не закрывается.
- Окно стало key, а пользователь кликнул в другое приложение — поле теряет фокус, данные сохраняются, панель сворачивается по обычным правилам.

## Не входит в задачу (Out of scope)
- Markdown/форматирование, вложения, картинки, чек-листы, теги, папки.
- Синхронизация (iCloud), шифрование, пароль на заметки.
- Отмена удаления, корзина, история версий.
- Импорт/экспорт, интеграция с Apple Notes.
- Глобальная горячая клавиша «новая заметка».
- Отслеживание внешних изменений файла (только проверка mtime перед записью).

## Принятые решения
- Q1: Как вводить текст, если NotchWindow не key и закрывается по уходу курсора? → Подтверждено: окно становится key только при клике в текстовое поле (`canBecomeKey` динамически); автосворачивание отключено, пока поле в фокусе; временная передача фокуса приложению допустима.
- Q2: Plain text или Markdown? → Plain text.
- Q3: Поведение при внешнем изменении файла? → Не отслеживаем; при конфликте mtime сохраняем `notes.conflict-<timestamp>.json`.
- Q4: Одна заметка или список? → Список.
- Q5: Удаление без подтверждения? → С подтверждением по умолчанию.

Открытых вопросов нет.
