# TASK-003: Виджет «Календарь» (EventKit)

## Бизнес-цель
Видеть ближайшие события и текущую дату, не открывая Calendar.app; за несколько минут до встречи получать ненавязчивое напоминание в peek.

## Зависимости
TASK-001 (протокол, peek, registry), TASK-002 (страница настроек виджета). `id: calendar`.

## Описание
Источник данных — EventKit (`EKEventStore`), т.е. все календари, настроенные в системе (iCloud, Google, Exchange). Только чтение.

**Compact (peek)**: показывается (`isActive = true`), когда есть событие, начинающееся в ближайшие N минут (`peekLeadMinutes`, по умолчанию 15) или уже началось не более 5 минут назад (Q3; значение «5 минут после начала» фиксировано, не настраивается; если событие короче — до его окончания). Содержимое: цветная точка календаря, название (усечённое), «через 12 мин» / «идёт». Приоритет 70.

**Expanded**: месячная сетка (текущий месяц, навигация ‹ ›, кнопка «Сегодня», подсветка текущего дня, точки у дней с событиями) + список событий выбранного дня (по умолчанию сегодня): время, название, место, цвет календаря. Всё-дневные события — сверху. Идущее событие подсвечено. Клик по событию — открывает его в Calendar.app (`ical://`/`x-apple-calevent://`, Q4). Если сетка + список не помещаются в базовый размер expanded (≈ 520×200, TASK-001), используется недельная полоса вместо месячной сетки (Q1).

**Настройки** (`widgets[].settings`):
- `peekLeadMinutes` (5/10/15/30, по умолчанию 15);
- `calendars`: список включённых календарей (по умолчанию все);
- `showAllDay` в peek (по умолчанию false);
- `firstWeekday`: системный / пн / вс (по умолчанию системный);
- `showDeclined` (по умолчанию false).

**Разрешения**: `NSCalendarsFullAccessUsageDescription` в Info.plist; `requestFullAccessToEvents()` вызывается лениво — при первом включении виджета или первом показе его вкладки, но не при старте приложения. Начиная с macOS 14 используется Full Access API (Write-only не подходит, Q5).

**Обновление данных (без опроса)**: подписка на `EKEventStoreChanged`; один таймер, выставленный точно на ближайшее значимое время (начало окна peek / начало / начало+5 мин / конец события / полночь); пересчёт при `NSWorkspace.didWakeNotification`, смене даты (`NSCalendarDayChanged`) и часового пояса.

## Состояния
- Нет разрешения (notDetermined): в expanded карточка «Нужен доступ к календарю» + кнопка «Разрешить».
- Отказано/ограничено (denied/restricted): текст-объяснение + кнопка «Открыть Системные настройки → Конфиденциальность → Календари». В peek не участвует.
- Нет событий на день: «Нет событий» (сетка работает).
- Нет календарей: «В системе нет календарей».
- Ошибка чтения: короткое сообщение, логируется, повтор при следующем `EKEventStoreChanged`.

## Критерии приёмки (Acceptance Criteria)
- [ ] AC-1: Дано виджет включён впервые и доступ не запрашивался, тогда системный запрос доступа показывается при первом включении/показе вкладки, а не при запуске приложения; пока запроса не было, при старте приложения диалог не появляется.
- [ ] AC-2: Дано доступ получен, тогда expanded показывает текущий месяц, сегодняшний день выделен, у дней с событиями есть индикатор.
- [ ] AC-3: Дано выбран день в сетке, тогда справа/снизу показан список его событий, отсортированный: всё-дневные, затем по времени начала.
- [ ] AC-4: Дано событие начинается через ≤ `peekLeadMinutes`, тогда виджет isActive и в peek (если он победитель по приоритету) показаны название и «через N мин» с актуальным значением (обновление раз в минуту только пока активно).
- [ ] AC-5: Дано событие началось, тогда в peek «идёт» в течение первых 5 минут после начала, затем виджет перестаёт быть isActive и peek гаснет без перезапуска (если событие короче 5 минут — по его окончании).
- [ ] AC-6: Дано несколько событий подряд/пересекающихся, тогда в peek ближайшее по началу (идущее раньше предстоящего); остальные — в expanded.
- [ ] AC-7: Дано в Calendar.app добавлено/изменено/удалено событие, тогда виджет обновляется ≤ 2 с без действий пользователя.
- [ ] AC-8: Дано доступ отклонён, тогда показан экран с инструкцией и работающей кнопкой, ведущей в нужный раздел Системных настроек; виджет не isActive; ошибок/падений нет.
- [ ] AC-9: Дано пользователь выключил календарь в настройках виджета, тогда его события нигде не отображаются, настройка сохраняется.
- [ ] AC-10: Дано наступила полночь или смена часового пояса, тогда «сегодня» и список пересчитываются без перезапуска.
- [ ] AC-11: Дано выход из сна, тогда данные и таймеры пересчитаны ≤ 2 с.
- [ ] AC-12: Дано виджет выключен, тогда нет подписок на EventKit и активных таймеров.
- [ ] AC-13: Дано событие с очень длинным названием/без названия, тогда название усекается (1 строка в compact, 2 в expanded), для пустого — «Без названия».
- [ ] AC-14: Дано клик по событию, тогда открывается Calendar.app на этом событии (или на дате, если открыть событие невозможно); панель не падает при ошибке.

## Нефункциональные требования
- В простое 0% CPU: ни одного периодического таймера, кроме одноразового «на ближайшее значимое время» и минутного тика только пока событие в окне peek.
- Запрос событий — диапазон не более видимого месяца ± неделя; выполняется вне main actor, результат передаётся на `@MainActor`.
- Данные календаря не покидают устройство, не логируются и не пишутся в config.json (в нём только настройки и идентификаторы календарей).
- Сборка без warning'ов, Swift 6 concurrency (EKEventStore не Sendable — изолировать в акторе).

## Граничные случаи
- Повторяющиеся события, события с исключениями (EventKit раскрывает сам).
- События через полночь, многодневные события — отображаются в каждом дне диапазона.
- Всё-дневные события и часовые пояса (floating-события не сдвигаются).
- Событие отменено/отклонено — по `showDeclined`.
- Календарь удалён, но его id остался в настройках — игнорируется.
- Пользователь отозвал доступ в Системных настройках при работающем приложении — переход в состояние «отказано», без падения (macOS может перезапустить процесс).
- Тысячи событий в день/месяц — лимит отображения и прокрутка.
- Смена системной локали/первого дня недели.

## Не входит в задачу (Out of scope)
- Создание/редактирование/удаление событий, ответ на приглашения.
- Напоминания (Reminders), задачи.
- Кнопка «Присоединиться» к видеозвонку (Zoom/Meet) — следующая итерация (Q2).
- Недельный/дневной вид как отдельный режим (недельная полоса — только запасной вариант по Q1), уведомления macOS.
- Календарные источники вне EventKit (прямой Google API).

## Принятые решения
- Q1: Сетка месяца или полоса недели? → Сетка месяца + список дня; если не помещается в базовый размер expanded (TASK-001 Q8) — недельная полоса.
- Q2: Кнопка «Присоединиться» к звонку? → Не в этой задаче; следующая итерация.
- Q3: «Идёт» в peek всю встречу или только начало? → Только первые 5 минут после начала, затем peek гаснет.
- Q4: Что делает клик по событию? → Открывает Calendar.app.
- Q5: Write-only или Full Access? → Только Full Access, отдельная формулировка в Info.plist.

Открытых вопросов нет.
