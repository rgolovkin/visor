# TASK-008: Виджет «Системный монитор» (CPU / RAM / сеть / диск)

## Бизнес-цель
Быстро увидеть нагрузку Mac (CPU, память, сеть, диск) при наведении на чёлку — и при этом **не создавать нагрузку самому**. Требование «0% CPU в простое» из правил проекта здесь критично, т.к. монитор по природе склонен к опросу.

## Зависимости
TASK-001, TASK-002. `id: sysmon`.

## Описание
**Принцип обновления (ключевое решение)**: сбор метрик выполняется **только пока виджет виден** — открыт expanded на его вкладке (или включён пороговый peek, см. ниже). Нет видимости → нет таймеров и нет сэмплирования. Опрос при видимости с интервалом 1–5 с (настройка, по умолчанию 2 с) — единственный допустимый вариант, т.к. у системы нет push-API для этих метрик; сэмплирование легковесное (Mach `host_processor_info`, `host_statistics64`, `getifaddrs`, `URLResourceValues`/`statfs`).

**Compact (peek)**: по умолчанию не активен. Включается пороговым режимом (`peekMode`: `never` | `onThreshold`; по умолчанию `never`, Q1). При `onThreshold`: CPU ≥ 90% или давление памяти «критическое» в течение ≥ 10 с подряд → peek с иконкой и значением; гаснет при возврате ниже порога − гистерезис 5%. Приоритет 30. Для работы порогового режима требуется фоновое сэмплирование с редкой частотой (раз в 5 с) — это единственный случай фонового сбора, и он включается только явной опцией.

**Expanded** (4 карточки):
- CPU: суммарная загрузка %, мини-график за последние 60 с, (опц.) по ядрам.
- Память: используется / всего (ГБ), давление памяти (норма/предупреждение/критично), swap.
- Сеть: скорость входящая/исходящая (КБ/с–МБ/с) суммарно по активным интерфейсам, мини-график.
- Диск: занято/свободно на системном томе, прогресс-бар. Обновляется раз в 30 с при видимости (скорость I/O — вне scope).
Топ процессов — вне scope (Q2).

**Настройки** (`widgets[].settings`): `refreshSeconds` (1/2/5, по умолчанию 2), `show`: набор включённых карточек (по умолчанию все), `peekMode`, `cpuThresholdPercent` (90), `networkUnit`: bytes/bits (по умолчанию bytes).

**Состояния**: ошибка получения метрики → «—» у карточки, остальные работают; сеть без активных интерфейсов → 0 КБ/с; недоступные данные не вызывают падение. Разрешений не требуется.

## Критерии приёмки (Acceptance Criteria)
- [ ] AC-1: Дано виджет включён, но вкладка не показана (expanded закрыт), `peekMode=never`, тогда нет таймеров сэмплирования; потребление CPU приложения ~0% (среднее < 0.5% за 60 с по `top`/Activity Monitor).
- [ ] AC-2: Дано открыта вкладка «Монитор», тогда значения обновляются каждые `refreshSeconds` и показывают данные, отличающиеся от Activity Monitor не более чем на ±5 п.п. (CPU) и ±3% (RAM).
- [ ] AC-3: Дано панель закрыта/свёрнута/вкладка переключена, тогда сэмплирование останавливается ≤ 1 тика; при повторном открытии первое значение показывается ≤ 1 с (без «прыжка» от нуля — первый сэмпл берёт дельту от предыдущего снимка).
- [ ] AC-4: Дано график CPU/сети, тогда он хранит последние 60 точек в кольцевом буфере (ограниченная память) и сбрасывается при выключении виджета.
- [ ] AC-5: Дано сеть, тогда скорости корректны при переполнении 32-битных счётчиков интерфейса и при сбросе счётчиков (отрицательная дельта → 0, не гигантский выброс).
- [ ] AC-6: Дано диск, тогда отображаются объём, занято и свободно системного тома в тех же единицах, что показывает Finder (decimal GB), с точностью до 1%.
- [ ] AC-7: Дано `peekMode=onThreshold` и CPU ≥ порога 10 с подряд, тогда виджет isActive и peek показывает значение; пока нагрузки нет — peek не виден.
- [ ] AC-8: Дано `peekMode=onThreshold`, тогда фоновое сэмплирование идёт не чаще 1 раза в 5 с и CPU, потребляемый самим приложением, < 1%.
- [ ] AC-9: Дано выключены некоторые карточки в настройках, тогда они не отображаются и их метрики не собираются.
- [ ] AC-10: Дано ошибка чтения одной метрики, тогда остальные карточки работают, на проблемной — «—».
- [ ] AC-11: Дано выключение виджета, тогда все таймеры/буферы освобождены.
- [ ] AC-12: Дано выход из сна, тогда первый сэмпл после пробуждения отбрасывается (искажённая дельта), графики не показывают провал/пик из-за сна.
- [ ] AC-13: Дано Swift 6 concurrency, тогда сэмплер работает в отдельном акторе/задаче, а на `@MainActor` публикуются только готовые значения.

## Нефункциональные требования
- Нагрузка самого сэмплирования при открытой вкладке: < 2% одного ядра при интервале 1 с.
- Только публичные/стабильные API (Mach host statistics, getifaddrs, statfs); без запуска внешних процессов (`top`, `vm_stat`) и без sudo.
- Без сторонних зависимостей.
- Метрики не сохраняются на диск, не отправляются в сеть. В config — только настройки.
- Формат настроек платформонезависим (метрики — enum-строки: `cpu`, `memory`, `network`, `disk`).

## Граничные случаи
- Apple Silicon: ядра P/E — суммарная загрузка по всем ядрам; per-core показывается без разделения P/E.
- Много сетевых интерфейсов (VPN, виртуальные, Docker) — учитывать физические активные (en*, исключая lo0) во избежание двойного счёта туннелей; правило фиксируется в плане.
- Тома: несколько дисков — показываем системный.
- Давление памяти: определение по `kern.memorystatus_vm_pressure_level` (sysctl) или эквиваленту; при недоступности — только процент.
- Очень быстрые переключения вкладок — без утечки таймеров.
- Низкий заряд/Low Power Mode — интервал не меняется автоматически (вне scope).

## Не входит в задачу (Out of scope)
- Список процессов и их завершение, GPU, температура/вентиляторы (требуют SMC/приватных API), энергопотребление.
- Дисковый I/O в реальном времени, история более 60 с, логирование метрик.
- Системные уведомления о нагрузке.
- Сетевая статистика по приложениям.

## Принятые решения
- Q1: Peek по порогам? → По умолчанию выкл. (`never`), чтобы гарантировать 0% CPU в простое; пороговый режим — опциональная настройка.
- Q2: Топ процессов по CPU/RAM? → Не в этой задаче (отдельно).
- Q3: Интервал обновления по умолчанию? → 2 с.
- Q4: Единицы сети? → Байты/с (КБ/с, МБ/с) по умолчанию, переключатель на биты.
- Q5: Температуры/вентиляторы/GPU? → Не входят (нет публичного API); возможна отдельная задача после согласования.

Открытых вопросов нет.
