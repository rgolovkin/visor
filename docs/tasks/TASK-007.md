# TASK-007: Виджет «Погода» (Open-Meteo)

## Бизнес-цель
Одним взглядом видеть текущую погоду и прогноз на ближайшие часы/дни без браузера и ключей API.

## Зависимости
TASK-001, TASK-002. `id: weather`. Внешний сервис: Open-Meteo (без ключа; бесплатно только для некоммерческого использования, см. «Риски и ограничения»).

## Решение по локации (принято, Q1)
**Ручной выбор города через геокодинг Open-Meteo** (`geocoding-api.open-meteo.com/v1/search?name=…`) — работает без системных разрешений, переносим на Windows, предсказуем. Автоопределение через CoreLocation (разрешение + `NSLocationUsageDescription`) — не в этой итерации; возможная опция «Использовать моё местоположение» позже. В config сохраняются: название, страна, `latitude`, `longitude`, `timezone`.

## Описание
**Compact (peek)**: по умолчанию **не активен** (приоритет 20). Опция в настройках «Показывать погоду в peek» (`peekMode`: `never` | `onChange` | `always`; по умолчанию `never`, Q2). При `onChange` — на 5 секунд при заметном изменении (например, начался дождь/гроза). Содержимое: иконка состояния + температура (°).

**Expanded**: город, текущая температура, ощущается как, описание (WMO weather code → текст+SF Symbol), ветер, влажность, мин/макс дня; почасовой прогноз на 24 часа (полоса); дневной на 5 дней по умолчанию (Q4). Время последнего обновления («обновлено 10:42»), кнопка «Обновить». В низу expanded — атрибуция «Weather data by Open-Meteo.com» со ссылкой (Q6).

**Настройки** (`widgets[].settings`): `location` (город/координаты), `units`: `metric`/`imperial` (по умолчанию из системной локали, Q3), `windUnit`, `peekMode`, `refreshMinutes` (15/30/60, по умолчанию 30), `forecastDays` (3/5/7, по умолчанию 5).

**Обновление данных**: без постоянного опроса. Запрос при: первом показе, открытии expanded, если кеш старше `refreshMinutes`; фоновое обновление — одноразовый таймер на момент устаревания **только если** peekMode ≠ never, иначе данные обновляются лениво при раскрытии. Выход из сна/смена сети (`NWPathMonitor`, подписка, не опрос) — обновить, если кеш устарел.
**Кеш**: последний ответ в `~/Library/Application Support/NotchApp/data/weather-cache.json` (+ `fetchedAt`), показывается сразу при открытии с пометкой возраста, затем обновляется.

**Состояния**: локация не выбрана → поиск города; идёт загрузка → скелетон/индикатор (кеш показывается, если есть); нет сети → кеш + «Нет подключения», без кеша — сообщение с «Повторить»; ошибка API/429 → кеш + «Не удалось обновить», экспоненциальная пауза повторов (макс. раз в 5 мин); город не найден → «Ничего не найдено».

## Критерии приёмки (Acceptance Criteria)
- [ ] AC-1: Дано виджет включён впервые, тогда показывается поиск города; системных диалогов разрешений нет.
- [ ] AC-2: Дано ввод ≥ 2 символов в поиске, тогда после дебаунса 400 мс запрашивается геокодинг, показывается список (город, регион, страна), поддерживается кириллица; при выборе локация сохраняется в config.
- [ ] AC-3: Дано локация выбрана, тогда expanded показывает текущую температуру, описание, ветер, влажность, ощущаемую температуру, мин/макс дня, и почасовой и дневной прогноз.
- [ ] AC-4: Дано температура в `units=imperial`, тогда значения в °F, ветер в mph; в `metric` — °C, км/ч (или м/с по `windUnit`).
- [ ] AC-5: Дано открытие expanded и кеш моложе `refreshMinutes`, тогда сетевой запрос НЕ делается; старше — делается, UI показывает кеш до прихода ответа.
- [ ] AC-6: Дано отсутствие сети при запуске, тогда показывается кеш с пометкой возраста, либо понятная ошибка с «Повторить»; приложение не падает и не зависает (таймаут запроса 10 с).
- [ ] AC-7: Дано ответ 429/5xx, тогда новые запросы не чаще 1 раза в 5 мин (backoff), UI остаётся на кеше.
- [ ] AC-8: Дано `peekMode=never`, тогда виджет не isActive и после показа expanded не создаёт таймеров/запросов в фоне (0% CPU, 0 сетевых запросов в простое).
- [ ] AC-9: Дано `peekMode=always`, тогда peek показывает иконку и температуру, актуальную в пределах `refreshMinutes`.
- [ ] AC-10: Дано изменён город, тогда кеш инвалидируется, данные запрашиваются заново, старые данные другого города не показываются.
- [ ] AC-11: Дано некорректный/неожиданный JSON ответа (отсутствуют поля, неизвестный weather code), тогда UI показывает доступные поля, неизвестный код — нейтральная иконка «—», без падения.
- [ ] AC-12: Дано виджет выключен, тогда отменены все сетевые задачи и таймеры, `NWPathMonitor` остановлен.
- [ ] AC-13: Дано время в прогнозе, тогда почасовая шкала показывается в часовом поясе выбранного города (`timezone=auto`), а не системном.
- [ ] AC-14: Дано запрос к сети, тогда используется только HTTPS и только домены api.open-meteo.com и geocoding-api.open-meteo.com; в запросы не уходит ничего, кроме координат/строки поиска.
- [ ] AC-15: Дано expanded с погодой, тогда внизу отображается кликабельная атрибуция «Weather data by Open-Meteo.com» (CC BY 4.0).

## Нефункциональные требования
- Приватность: координаты города отправляются стороннему сервису — это должно быть указано в «О приложении»/описании виджета. Идентификаторы пользователя, IP-логирование на нашей стороне отсутствуют.
- Сетевые запросы через `URLSession` с таймаутом, вне main actor; декодирование `Codable`; ответы кешируются в нашем формате, не в URLCache.
- Нагрузка: ≤ 1 запрос на refresh-интервал; 0% CPU в простое.
- Платформонезависимо: конфиг локации и кеш — JSON (WMO-код хранится числом, маппинг на иконки в клиенте).
- Строки состояний погоды локализуются (ru/en).

## Граничные случаи
- Разные города с одинаковым названием — различать по региону/стране.
- Ночь/день для иконки (`is_day`).
- Полярные широты, нет данных осадков.
- Смена системной локали единиц.
- Часы системы и сервера расходятся — используем `fetchedAt` локально.
- Прокси/VPN, captive portal (ответ не JSON) — обрабатывается как ошибка парсинга.
- Очень длинное название города — усечение.
- Просыпание из сна с неподключённой сетью — запрос отложен до `NWPathMonitor` satisfied.

## Не входит в задачу (Out of scope)
- Несколько городов, карты осадков, радар, предупреждения о ЧС, качество воздуха, UV, пыльца.
- Автоопределение геолокации (CoreLocation) — возможная следующая итерация.
- Другие погодные провайдеры, ключи API.
- Системные уведомления о погоде.

## Риски и ограничения
- **РИСК (отложено осознанно, решение человека до публичного релиза):** лицензия Open-Meteo. Бесплатный доступ — только для некоммерческого использования; при коммерческом распространении потребуется платный план или self-host. На старте проект считается некоммерческим. До публичного релиза необходимо подтвердить статус проекта и при необходимости сменить план/провайдера. Всё обращение к API изолировано в одном клиенте, чтобы замена не затрагивала UI.

## Принятые решения
- Q1: Локация — вручную или CoreLocation? → Вручную (геокодинг Open-Meteo), без разрешений; CoreLocation — позже.
- Q2: Погода в peek? → По умолчанию нет (`peekMode=never`).
- Q3: Единицы по умолчанию? → По системной локали (`Locale.measurementSystem`).
- Q4: Сколько прогноза? → 5 дней и 24 часа.
- Q5: Коммерческий ли продукт? → Считаем некоммерческим на старте; решение до публичного релиза отложено (см. «Риски и ограничения»).
- Q6: Атрибуция Open-Meteo в UI? → Да, ссылка «Weather data by Open-Meteo.com» внизу expanded (CC BY 4.0).

Открытых вопросов нет, кроме осознанно отложенного риска лицензии.
