# TASK-001: Ядро — NotchWindow, состояния, WidgetRegistry, config.json, меню-бар (Milestone 1)

## Бизнес-цель
Получить каркас продукта: плавная «чёлка» над любым экраном, в которую подключаются виджеты. Плавность анимаций и нулевая нагрузка в простое — ключевая ценность. Все остальные задачи (002–008) строятся на контрактах этой задачи.

## Зависимости
Нет. Блокирует TASK-002..008.

## Описание
1. **NotchWindow** — `NSPanel` без рамки, прозрачный, не крадёт фокус, виден на всех Spaces и поверх полноэкранных приложений (параметры — раздел «Архитектура» правил проекта). **Единственное исключение** из «не key»: окно временно становится key только при клике в текстовое поле виджета (`canBecomeKey` динамически, нужно для TASK-006 «Заметки», см. Q9); во всех остальных случаях оно key/main не становится.
2. **Геометрия**: на экране с чёлкой окно совпадает с чёлкой (`safeAreaInsets.top`, `auxiliaryTopLeftArea/RightArea`); на экранах без чёлки и внешних мониторах рисуется виртуальная «пилюля» по центру сверху.
3. **Мультимонитор**: по умолчанию окно на одном экране (режим `auto`, см. Q1); реакция на `didChangeScreenParametersNotification` (подключение/отключение, смена разрешения, смена главного экрана).
4. **Состояния**: `collapsed` → `peek` → `expanded`.
   - collapsed: только форма чёлки/пилюли, ничего не показывается (на экране с чёлкой визуально не отличимо от железа).
   - peek: чёлка расширяется влево/вправо, показывая compact-вид виджета-победителя (наибольший `priority` среди `isActive` включённых виджетов). Если активных нет — peek не показывается.
   - expanded: панель вниз с вкладками (с иконками) включённых виджетов в порядке из конфига, размер ≈ 520×200 pt (Q7, Q8).
5. **Hover**: наведение на область чёлки/пилюли → expanded с задержкой открытия 150 мс; уход курсора → сворачивание с задержкой 300 мс (Q2). Клик по peek → expanded немедленно. Пока в текстовом поле виджета идёт ввод (поле в фокусе, в т.ч. IME-композиция), автосворачивание по уходу курсора отключено; оно возобновляется после потери фокуса полем/клика вне панели. Без опроса в цикле: `NSTrackingArea` и/или `NSEvent.addGlobalMonitorForEvents`.
6. **Анимации**: spring-анимации между всеми состояниями, без дёрганий и мерцания контента; прерываемые (смена направления в середине анимации не ломает состояние). При Reduce Motion — короткий fade 150 мс (Q5).
7. **Протокол `NotchWidget`** (исходный набросок) + расширения, которые фиксирует эта задача:
   - стабильный строковый `id` (используется в config.json, платформонезависимый): `clock`, `calendar`, `timer`, `battery`, `weather`, `sysmon`, `notes`;
   - способ получить настройки виджета: `settingsSchema`/`makeSettingsView()` — необязательные, по умолчанию пусто (используется в TASK-002);
   - `isActive` изменяется реактивно (`@Observable`), без опроса со стороны ядра;
   - жизненный цикл `activate()/deactivate()` — вызывается при включении/выключении виджета; выключенный виджет не потребляет ресурсов (таймеры, наблюдатели, сеть).
8. **WidgetRegistry** (`@Observable`): список зарегистрированных виджетов, порядок, включённость; персист в JSON.
9. **config.json** — `~/Library/Application Support/NotchApp/config.json`:
```json
{
  "schemaVersion": 1,
  "general": { "launchAtLogin": false, "displayMode": "auto", "displayId": null },
  "widgets": [
    { "id": "clock", "enabled": true, "settings": {} }
  ]
}
```
   `displayMode`: `auto` (по умолчанию: экран с физической чёлкой, иначе главный) | `primary` | `notch` | `display` (конкретный экран, идентификатор в `displayId`). Порядок массива `widgets` = порядок виджетов. Формат платформонезависим: только JSON-примитивы, ISO-8601 для дат, никаких Swift-специфичных типов. `settings` каждого виджета — произвольный JSON-объект, владелец схемы — сам виджет (все настройки виджетов в TASK-003..008 хранятся именно в `widgets[i].settings`). Неизвестные поля и неизвестные `id` сохраняются при перезаписи (не теряются).
   Пользовательские данные виджетов (заметки, состояние таймера, кеш погоды) лежат отдельно в `~/Library/Application Support/NotchApp/data/` (`notes.json`, `timer.json`, `weather-cache.json`) и не входят в config.json; сброс настроек их не удаляет.
10. **Тестовый виджет «Часы»** (`id: clock`): compact — время `HH:mm` (формат по системной локали), expanded — время с секундами и дата. Обновление — по границе минуты/секунды, а не частым таймером; секундный тик только пока expanded.
11. **Иконка в меню-баре**: пункты «Настройки…» (⌘, — открывает окно из TASK-002; до её готовности пункт неактивен или открывает заглушку) и «Выйти» (⌘Q).

## Приоритеты peek (общая шкала, фиксируется здесь)
Больше = важнее. Виджеты используют значения: Таймер (`timer`) 90, Батарея 80 (только при событии), Календарь 70, Системный монитор 30 (только при превышении порогов), Погода 20 (по умолчанию не активна), Часы 10, Заметки 0 (никогда не в peek). При равенстве — выше в порядке конфига. Следствие шкалы: пока идёт таймер/Pomodoro, peek низкого заряда батареи и событий календаря не виден (виден в expanded); принято осознанно.

## Критерии приёмки (Acceptance Criteria)
- [ ] AC-1: Дано Mac с чёлкой, когда приложение запущено, тогда окно расположено по границам чёлки на целевом экране без смещения > 1 pt и не отображает видимого контента в collapsed.
- [ ] AC-2: Дано Mac без чёлки или внешний монитор, когда приложение запущено, тогда сверху по центру отображается виртуальная пилюля размером не менее зоны наведения 200×24 pt.
- [ ] AC-3: Дано collapsed, когда курсор входит в область чёлки и остаётся дольше 150 мс, тогда панель плавно переходит в expanded spring-анимацией.
- [ ] AC-4: Дано expanded, когда курсор покидает панель и остаётся вне её дольше 300 мс, тогда панель плавно сворачивается (в peek, если есть активный виджет, иначе в collapsed).
- [ ] AC-5: Дано быстрое вхождение-выход курсора (< 150 мс), тогда панель не открывается.
- [ ] AC-6: Дано анимация раскрытия в процессе, когда курсор уходит, тогда анимация плавно разворачивается из текущего положения без скачка.
- [ ] AC-7: Дано включённые виджеты с isActive=true и разными priority, когда состояние collapsed, тогда в peek показывается compact-вид виджета с наибольшим priority; при равенстве — того, что выше в порядке конфига.
- [ ] AC-8: Дано peek с виджетом A, когда у виджета с большим priority isActive становится true, тогда peek плавно переключается на него; когда он снова false — возвращается к A.
- [ ] AC-9: Дано нет ни одного isActive-виджета, тогда peek не отображается, окно в collapsed.
- [ ] AC-10: Дано приложение работает, когда пользователь работает в других приложениях, тогда NotchWindow не становится key/main окном, не забирает фокус, не появляется в Cmd+Tab/Dock/Mission Control. Исключение: клик в текстовое поле виджета (TASK-006) делает окно key до потери фокуса полем.
- [ ] AC-11: Дано полноэкранное приложение или другой Space, тогда чёлка по-прежнему доступна (hover работает).
- [ ] AC-12: Дано подключение/отключение внешнего монитора или смена разрешения, тогда окно за ≤ 1 с корректно перепозиционируется без перезапуска; если целевой экран исчез — переезжает на главный.
- [ ] AC-13: Дано отсутствие config.json (первый запуск), тогда создаётся config с дефолтами (все реализованные виджеты включены в порядке: Часы, Календарь, Таймер, Батарея, Погода, Системный монитор, Заметки; `displayMode: auto`) и приложение стартует без ошибок.
- [ ] AC-14: Дано повреждённый/нечитаемый config.json, тогда он переименовывается в `config.json.broken-<timestamp>`, создаётся дефолтный, приложение не падает.
- [ ] AC-15: Дано config с `schemaVersion` больше известного, тогда приложение читает известные поля, не перезаписывает файл «в меньшую версию» (бэкап + предупреждение в лог).
- [ ] AC-16: Дано config с неизвестным widget id, тогда запись сохраняется при последующих сохранениях и не вызывает ошибок.
- [ ] AC-17: Дано изменение включённости/порядка в registry, тогда config.json обновляется атомарно (запись во временный файл + rename) с debounce ≤ 500 мс.
- [ ] AC-18: Дано виджет выключен, тогда его `deactivate()` вызван, у него нет активных таймеров/подписок/сетевых запросов, и он не отображается ни в peek, ни в expanded.
- [ ] AC-19: Дано виджет «Часы» включён, тогда compact показывает время, корректное по системной локали/часовому поясу, обновляется в начале каждой минуты; изменение системного времени/часового пояса/выхода из сна отражается ≤ 1 с.
- [ ] AC-20: Дано меню-бар, тогда иконка содержит «Настройки…» и «Выйти»; «Выйти» завершает приложение.
- [ ] AC-21: Дано приложение запущено повторно (второй экземпляр), тогда второй экземпляр завершается, первый остаётся.
- [ ] AC-22: Дано expanded открыт и текстовое поле виджета в фокусе, когда курсор уходит с панели, тогда панель не сворачивается; после потери фокуса полем (или клика вне панели) сворачивание происходит по обычным правилам (300 мс).
- [ ] AC-23: Дано expanded, тогда навигация — вкладки с иконками в порядке конфига, последняя выбранная вкладка запоминается между открытиями; размер панели ≈ 520×200 pt.

## Нефункциональные требования
- Swift 6 strict concurrency, UI-код на `@MainActor`; warnings = errors; `make build` без ошибок.
- Простой (collapsed, нет активных виджетов): ~0% CPU (измеряется Activity Monitor/`top` за 60 с, среднее < 0.5%), нет периодических таймеров с периодом < 60 с у ядра.
- Анимации держат 60 fps (ProMotion — 120) на M-серии; нет потери кадров при переходах (проверка вручную + Instruments).
- Память ядра в простое < 60 МБ.
- Минимальная ОС macOS 14; нет сторонних зависимостей.
- Логирование через `os.Logger`, без PII.

## Граничные случаи
- Несколько экранов с чёлкой/без; закрытая крышка с внешним монитором (clamshell); смена режима зеркалирования.
- Экран в режиме масштабирования, меняющем размер чёлки (safeAreaInsets меняется).
- Меню-бар в автоскрытии: чёлка по-прежнему на месте.
- Курсор уходит на другой экран во время expanded — сворачиваем (если не идёт ввод в текстовом поле).
- Перетаскивание файла/клик на пересечении с меню-баром — не должно блокировать клики в меню-бар вне зоны чёлки (окно не шире нужного, `ignoresMouseEvents` вне интерактивной области).
- Нет места для compact (слишком широкий compact-вид) — обрезается/ограничивается максимальной шириной.
- Config недоступен для записи (read-only, нет места) — работаем в памяти, лог, без падения.
- Ручное редактирование config пользователем во время работы: не отслеживаем (см. out of scope).
- Reduce Motion в системе: анимации заменяются на упрощённые (fade 150 мс).

## Не входит в задачу (Out of scope)
- Окно настроек (TASK-002), реальные виджеты (TASK-003..008).
- Now Playing, файловая полка, замена HUD, HTTP API, плагины.
- Горячие клавиши для раскрытия, жесты, режим «только клик» (в настройки — позже).
- Режим «на всех экранах», два независимых peek-слота, сетка виджетов вместо вкладок.
- Наблюдение за изменениями config.json на диске.
- Переключатель языка (UI следует системному языку; строки выносятся в String Catalog, ru + en).
- Sparkle, notarization.

## Принятые решения
- Q1: На скольких экранах показывать чёлку? → Один: экран с физической чёлкой, иначе главный (`displayMode: auto`). Выбор экрана («Авто / Основной / С чёлкой / конкретный») — в TASK-002. «На всех экранах» — не в M1.
- Q2: Hover или клик? Задержки? → Hover: открытие через 150 мс, закрытие через 300 мс; клик по peek открывает немедленно. Режим «только клик» — позже.
- Q3: Порядок и включённость по умолчанию? → Включены все, порядок: Часы, Календарь, Таймер, Батарея, Погода, Системный монитор, Заметки. Часы остаются в дефолтной конфигурации (тестовый виджет; пользователь может выключить).
- Q4: Один виджет в peek или два? → Один победитель; его compact-вид может занимать обе стороны (leading/trailing). Два слота — позже.
- Q5: Reduce Motion? → Spring заменяется коротким fade (150 мс).
- Q6: Язык интерфейса? → Русский + английский через String Catalog, по системному языку; переключателя в приложении нет.
- Q7: Навигация в expanded? → Вкладки с иконками по порядку из конфига, последняя выбранная запоминается. Сетка — позже.
- Q8: Размер expanded? → Фиксированный базовый ≈ 520×200 pt, виджеты подстраиваются; высота анимированно меняется только при смене вкладки.
- Q9: Ввод текста при не-key окне (Заметки)? → Окно становится key только при клике в текстовое поле; автосворачивание отключено на время ввода (AC-22).

Открытых вопросов нет.
